# Original local queue controls

The phone's queue selector exposes the translated VietK selected and download lists separately from the yt-dlp queue. Rows use `local:<FlowId>` and `download:<FlowId>`, so repeated orders of one song remain distinct. Source selection changes the list being edited, while playback buttons operate on the current native player.

Original local rows use `OriginalSelectedQueue` for priority, drag/reorder and deletion, including its existing one-based delete/top DAO messages and zero-based sort messages. Shuffle and clear-except-playing now follow `SelectedLocalListManager`: runtime state changes without an invented DAO message. Download rows expose their actual percentage/error/waiting state and use the existing download-list removal/priority methods. Clearing the original queue retains a playing local head and cancels the download list. Download-row drag and cross-list priority are unavailable; the native download manager has no translated sort operation.

Native playback records whether its source is idle, local karaoke or YouTube. Switching to local karaoke cancels an ongoing yt-dlp transfer and prevents it reclaiming playback later. The YouTube handler no longer consumes the local player's next/completion commands. Local next advances the original selected queue, and its final removal restores idle video. Editing saved YouTube rows while a local song plays preserves that playback. A normal YouTube add waits during local karaoke; explicit sing-now or retry can start YouTube. Valid local vocal controls remain routed to the native decoder.

The original `Đã chọn` route opens the local/download list during local playback, using the existing in-panel dialog without YouTube badges on normal-song rows. Confirmed queue changes update the badge and current/next TV marquee. Original sung history, MIDI/other-service row badges, full storage discovery, manufacturer song downloads and a unified factory mixed-service playback list remain incomplete. The local phone page is a replacement LAN interface; it does not recreate or authenticate the hosted manufacturer's website.

Verification uses real native HTTP, the actual queue classes and SQLite selected-list storage, synthetic local media and a synthetic download callback. It checks duplicate identities, priority/move/delete, protected shuffle/clear, download progress/cancellation, next routing, idle recovery and isolation from saved YouTube rows. Chromium clicks the original queue selector and priority button against the native server. This does not establish manufacturer cloud availability or physical phone/Wi-Fi connectivity.

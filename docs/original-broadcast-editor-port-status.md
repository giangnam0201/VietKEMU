# Original local idle-playlist editor

The Firefox/options menu now opens `Video màn hình chờ…`, backed by the original idle-song configuration. The implementation follows decoded `BroadcastListSettingDialog`, `AddBroadcastListDialog`, `PublicPlaySongPageLoadPresenter` and `SongDAO.getSongBySpellName`.

The main dialog uses the original 680 by 538 layout, 60-pixel title, 50-pixel column header, 240-pixel list and 60-pixel rows. Top moves a draft row to index zero; delete removes that row. Cancel and outside dismissal discard the draft. Confirm saves string `song_id` and `type` fields plus `is_need_reply`, preserving duplicate raw entries. Runtime playback still deduplicates IDs as the original manager does. Nonlocal row clicks and confirmed nonlocal entries use the existing original song-order route, including its actual availability gates. Saving does not interrupt a currently playing idle video; the revised list applies to the next selection.

Create-new hides the parent and opens the add dialog, centered 45 pixels above the center, with the original 19-pixel root padding, 45-pixel input/search rows, 320-pixel search list and 200-pixel draft list. Typing searches initial, name and English-name prefixes in 50-result database pages; spell-prefix matches sort first, followed by spell length, preferred language and play count. Visibility, PSL and MIDI filtering retain the original SQL branches, including filtering MIDI after LIMIT. Scrolling to the bottom loads the next page. Selecting a result returns to the draft without clearing the input. Add-screen delete edits only that draft; back discards additions and returns to the parent; its confirmation appends them to the parent's unsaved list. Outside/Escape dismissal closes both screens without saving additions. Duplicate selections remain allowed.

The port uses original top/delete artwork from the owner's local supplemental archive when present, with drawn fallbacks otherwise. The recovered empty-list artwork is packaged locally only. The publicly built app can therefore show the fallback music symbol. WPF radio controls, the online badge and the smaller translated add-confirm label are Windows adaptations, not exact original artwork/text rendering.

USB selection currently uses the existing Windows video picker. The original USB scan/copy/progress/delete dialogs, linked/cloud mode and blank-input rank-file search branch remain pending. No original media-server access is implied by the editor. The selected list cannot play music whose media is unavailable.

The combined grid-animation, playback and phone tests also passed. The separate public YouTube probe still encountered the runner's bot sign-in challenge and did not download or decode that public video. Physical phone Wi-Fi, original cloud access and complete hardware/UI equivalence are unverified. No app build ZIP was downloaded to the owner's PC.

Phone-control evidence: original commands 102/103 get broadcast state/set the local list. `SetBroadcastLocalListRequest` uses `publishMusicOfLocal` records with integer `songid`, string `songname` and string `singername`. `SettingAction.setBroadcastLocalList` saves IDs through `setBroadcast(0, songs)` and builds the reply from actual database songs; `getBroadcastState` reads the generated runtime list. Thus saved-list replies and runtime-state replies differ when raw entries contain duplicates or missing database IDs. The [phone editor](original-mobile-broadcast-playlist-port-status.md) now connects these semantics to the paired local API and shares its save controller with the desktop dialog; see its document for current verification and remaining differences.

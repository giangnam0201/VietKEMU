# Blank-input idle-song ranking search

`AddBroadcastListDialog` opens search on an empty-input click or Enter; clearing the input returns to the added-song draft. Its `PublicPlaySongPageLoadPresenter` reads rank 0 from `rankcache/0.txt` when there is no search text. The port now follows those transitions on the desktop and paired phone, using the shared `OriginalBroadcastRankCache` reader.

The cache is the original Java list text, for example `[101002/0, 101001/0, 101002/1]`. The reader takes a raw 50-record page before resolving database IDs. It preserves order and duplicates, skips absent/nonpositive database IDs, applies the original nonempty-name, PSL and local/connected visibility checks, and stops a malformed page after its preceding valid results. Song type is validated as the original parser does; it does not invent song metadata. A missing/unreadable cache produces no results rather than a different database ordering.

Production reads `<VietK state directory>/rankcache/0.txt`, normally `%LOCALAPPDATA%/VietKNativePort/rankcache/0.txt`. This adds the cached branch; automatic manufacturer rank refresh and its network/account dependencies are not ported. No real ranking file was recovered from the available firmware/reference inventory. The browser supports a blank `q` on its existing paired search route. Nonempty queries keep the original name/initial/English prefix query.

The Android presenter can request another page even after filtering reduces the visible count. Desktop scrolling and phone scrolling/More now continue after a nonempty partial page instead of requiring exactly 50 rows. The port stops after an empty result page. This preserves the original raw page boundaries; it does not fill gaps with later rows from a different page.

Verification is pending the GitHub Windows build. Core checks cover original order/duplicates, raw slices before filtering, PSL and connection gates, and missing/malformed caches. Native desktop interaction uses an actual synthetic rank file, clicks the empty input, selects a ranked song without modifying its input, and also checks scrolling after a 49-row filtered page. Actual HTTP and phone browser checks load a rank page with three known entries plus 47 missing IDs, then request the ten entries in the next raw page. Synthetic cache/metadata proves transport and behavior, not live manufacturer rank availability.

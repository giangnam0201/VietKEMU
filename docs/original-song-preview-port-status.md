# Original song preview

The song grid and collection browser now route their preview buttons to the original `PreviewDialog` behavior. A 650×530 modal stays inside the existing panel window, with a 450×253 video surface, title/singer header, close, “Chọn bài” and “Bộ sưu tập” controls at the APK's positions. The modal has no background dim. Outside click and Escape dismiss it. Ordering uses the existing original order executor; favorites use the existing collection/profile flow. Queue changes update the original title/singer highlight colors.

Preview uses a separate, muted Windows decoder: the current television decoder and its shared manager preview continue unchanged. It starts at the beginning, reveals decoded video after the original 800ms delay, loops on completion, and releases its decoder when dismissed or replaced. Missing local media shows “Tải video không thành công”; it does not pretend a server URL exists. The preview currently resolves the original media metadata through the port's confirmed local music cache. Manufacturer microservice/hot-movie URL tasks and additional storage discovery remain pending.

Original button and close artwork is recovered only into the owner's local supplemental archive by `package_ambience_reference.py`. No new firmware media is published. Builds without that private archive use text controls; verification reports artwork availability. Android middle ellipsis and entrance animation are not yet translated exactly. The source layout's unused lower space is retained rather than inventing additional controls.

Native verification decodes a synthetic real video, checks preview frames and independent TV frame delivery, mute state, the order/favorite callbacks, queue highlighting, actual end-of-media loop restart, decoder release, missing-file messaging and rapid close. It captures synthetic song data only. This verifies the local preview path, not manufacturer download availability or complete APK fidelity.

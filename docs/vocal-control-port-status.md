# Vocal control from the panel and phone

The APK's `PlayControlAction.playControl` value 4 calls `checkCanSwitchTrack` before `switchTrack`. `KmPlayCtrlUtil.checkCanSwitchTrack` rejects absent media metadata and `ResourceTypeUtil.getStereoAudioType` identifies `(0,5)` as original-only stereo and `(5,0)` as accompaniment-only stereo. Those resources must retain both stereo channels; the absent mode is not another channel to select.

The Windows port preserves stereo for both single-mode metadata combinations and rejects the vocal toggle there, on idle video and on YouTube video without original karaoke track metadata. The local phone page displays the same native availability and confirmed vocal state, with a disabled button and explanatory text when switching is unavailable. The phone uses the existing panel commands, actual native audio switching, confirmed panel icon and original TV feedback images. The YouTube screen no longer intercepts valid vocal commands during local karaoke playback.

Verification clicks the phone control in a real Chromium browser against native HTTP. Separate HTTP checks measure decoded left/right test tones after each vocal switch and check the confirmed panel and TV feedback. Native stereo-only fixtures verify that both channels remain intact before and after an unavailable toggle for each metadata combination. Idle state and commands cannot claim an available vocal mode. Synthetic audio verifies routing; it does not prove the metadata of every factory song, manufacturer mobile website compatibility, or vocal removal from a normal YouTube stereo mix.

# Original singer song navigation

The default song grid and collection rows now render the APK's separate clickable singer spans. Each comma-separated name requests that name from `SingerDAO.getSingerByName`, including its original English-name substring branch. Unknown names leave the current screen intact. Clicks on names do not order the parent song.

`OriginalSingerNavigation` implements fragment 28 using the same song-browser layout that the APK's `SingerSongNameFragment` inherits. Its category title is the selected singer's name; its filtered songs use all four `SongsterID` fields, original local/connected-online visibility, PSL and language/length rules, sort order, 60-record SQL pages and MIDI filtering after LIMIT. The spell branch uses prefix matching; the two name branches retain the APK's counterintuitive `isFuzzyAfter` behavior. The native keyboard currently exposes the spell path. Alternate name/handwriting input remains pending.

Scrolling appends the next singer page after settling, preserving the original `lastVisible > count/3` threshold and unchanged-total guard. An empty filtered page does not refill itself from subsequent SQL pages. The Windows settle timer substitutes for Android's idle-scroll callback. Favorites, order, priority and local preview use the existing common handlers. Queue and favorite confirmations refresh current and retained singer screens.

The shipped local seed has zero singer records. The original `SingerDAO.createLocalSinger` import is now applied after online song/media metadata import, copying only singers referenced by song rows from the whole catalogue, with INSERT OR IGNORE persistence. The original local singer schema is upgraded with its English-name field. These rows describe metadata; they do not prove manufacturer media or cloud availability.

Back restores the actual previous view object, retaining its keyboard input and scroll position, including nested singer views and the collection sidebar. The category action opens original fragment 1, the singer directory; its filters, paging and remaining fidelity work are described in [the directory status](original-singer-directory-port-status.md). Directory cards open the exact singer ID rather than resolving a duplicate name. The default 27×27 rounded singer portrait is recovered only into the owner's private supplemental archive. Manufacturer singer-picture URL/cache resolution remains pending. Builds without that archive leave the portrait area empty and retain its geometry.

Core checks verify all four singer slots, duet separation, English lookup, local/remote/PSL filtering, empty spell, prefix/substring branches, ordering and post-LIMIT MIDI behavior. Native checks use synthetic data to exercise the actual links, second duet singer, original page size and append, singer-scoped keyboard search, confirmed favorite icon/common callback, nested and collection Back, unknown-singer no-op, category fragment request and two-window operation. Neither these checks nor this feature claim complete singer-directory or complete firmware parity.

# Idle-video volume and mute

The original `BroadcastVolumeSettingDialog`, `AudioManagerUtil` and `BottomMenuBarView` separate idle/broadcast volume from song volume. Persisted keys are `broadcast_volume` (default 15, UI range 0–20) and `is_broadcast_mute` (default false). `AudioManagerUtil` caches both at initialization. The dialog says “Hiệu quả sau khi khởi động lại”: editing config does not change the cached live values. Idle +/- updates the session broadcast volume, while song +/- updates the song volume. A configured idle mute prevents idle volume adjustment.

The Windows port now keeps these preferences and session values separately. Starting idle uses the cached idle gain; returning to a song restores its session gain. Saving configuration from desktop or phone leaves current playback untouched and takes effect on the next app instance. Idle mute uses zero output only for idle media and does not mute the next song. Live global mute remains separate.

The native editor follows `dialog_setting_broadcast_volume` / `Common1Dialog`: 500-pixel width, centered title, mute toggle, original seekbar/icons where available, restart notice and no confirmation/cancel action. Closing through outside tap or Escape saves the draft. Muting zeros/disables the slider; unmuting leaves zero. Public builds use fallback icons if the owner-local supplement is absent. The complete original settings screen and hardware stream-volume implementation remain unported.

Paired GET/POST `/api/settings/broadcast-volume` retains `publishVolume`, `isMuteOfPublishVolume` (`"0"`/`"1"`) and `maxPublishMusic`, adding the restart notice. Validation rejects invalid bodies without changing config. The phone details editor saves on closing and reproduces staged mute/zero/disabled-slider behavior; its layout is adapted for a browser, not a claim of original phone-client visual parity.

Core checks cover independent persistence, limits and song-default isolation. Native checks exercise actual decoded PCM power, song/idle transitions, session-only +/- changes, restart-applied mute and desktop dialog events, and capture a synthetic dialog. Real HTTP checks cover original fields, invalid input, authorization/origin/revocation and live-state preservation. Phone browser checks cover mute, zero after unmute, save-on-close and restoration without resuming paused playback. Windows verification is pending; physical hardware audio equivalence and physical-phone Wi-Fi behavior are unverified.

# Original local song collections

The song-grid favorite buttons now use the APK's active `MuiltCollectListManager` path rather than the older customer-ID DAO. A first favorite opens the translated `CollectLoginDialog` inside the existing control-panel window. Successful login retries that song, saves its ID and refreshes the original collected icon. Clicking again removes it. TV playback continues independently.

`CollectInputPwdView`, `CollectFileManager` and `CollectLoginManager` define the local profiles: four-to-twelve-character names/passwords, automatic profile creation for a new name, password checking for existing names, independent ordered song lists and a remembered current profile. The modal applies slash-to-underscore calibration; `CollectFragment`'s inline form does not. The original `kmbox/muilt_collect/<username>-VietK-<password>` UTF-8 line format is retained below the port's local state directory, with a 150-song addition limit. These are local collection passwords, not manufacturer or YouTube credentials. The original file format exposes the local password in its filename; do not use a password shared with another account. The port never logs these names/passwords or sends them to a server.

The modal follows `dialog_input_pwd.xml` and `view_collect_input_pwd.xml`: 480-wide content, 60-high heading, 288-high form, 245×50 fields, original positions, colors, rounded cyan confirmation button and Vietnamese strings. Windows text/password controls and Escape replace the Android input method/back action. Toast rendering and Android keyboard handling are not identical yet. The original initial `AnimationUtil` direction is zero, which applies no entrance translation. Profile login/logout is also accessible through the panel's existing options menu.

The original More tile `fl_favorite` now requests fragment 14 and opens `OriginalCollectionBrowser`. It follows `view_personal_collect.xml`, including the 355×490 account panel, inline login/progress/logout, 744×490 list, category/home action and original back control. `CollectFragment.initRecylerView` actually creates a vertical `LinearLayoutManager` and `SongRecyclerAdapter`, which inflates 744×74 `fragment_song_recycler_long_item` rows. Its two-column/four-row constants and pager methods are unused: `initChangePageView` is never called, and the fragment switch hides the global pager. The translated screen therefore uses continuous scrolling and the original six-item, three-pixel indicator. Its nonlinear thumb formula, alternating row tint, queue hints, online-head offset, two-line titles/singers, action positions and 250ms right-in animation come from the active handlers. The DAO fetch uses 192 IDs before filtering; the normal 150-favorite limit fits a single fetch.

Order and priority callbacks use the existing original order executor. `SongItemAnim` draws a temporary row and applies its 500ms translation to (1000,550), original (30,56) origin subtraction, scale to 0.2 and alpha to 0.4, then removes the row. The collection callback refreshes the star without re-querying/removing the displayed row, matching `onCollectListChange`; the next screen load uses the saved collection. Profile changes rebuild the list. Queue/download changes update labels and local metadata. The inline form preserves its hidden field spacing after login and clears fields on logout/failed login. Android keyboard layout changes, its progress animation and the adapter's explicit Android condensed font remain platform differences.

The Windows control panel now opens fully within the primary desktop's working area and scales the original 1280×800 canvas. This prevents right/bottom controls from opening off screen on smaller displays. Native verification uses the same window factory and checks real pointer positions inside the action controls, rather than treating an off-screen synthetic click as a successful action.

The recovered `icon_favorite_for_login` remains in the owner's private local supplemental ZIP (`ambience/collection`), generated by `tools/package_ambience_reference.py`. No new firmware artwork is uploaded. When this local resource is unavailable, the account panel omits that illustration; native reports state whether it was available. Collection preview and singer-navigation handlers, MIDI artwork/playback and song-update badges remain incomplete, so this is not a claim that every collection action or every visual detail is already 1:1.

Windows-incompatible filename characters are rejected. Saves use a temporary file plus replacement, so an unsuccessful save retains the confirmed collection and icons. The collection query retains original ordering: page song IDs before metadata lookup and local/connected-online/PSL filtering. Core checks exercise independent profiles, wrong passwords, restart/logout, insertion order, original file format, an actual locked-file write failure, imported duplicate/invalid IDs, modal versus inline calibration, filtering and the limit. Native Windows checks click the actual modal/grid and browser controls, inspect confirmed/uncollected resources, verify persistence, cancel/failed login, progress state, continuous scroll, More/back routes, queue labels, retained-row recollection and two-window operation. Reports contain synthetic fixtures only; profile files stay outside report artifacts.

Normal sung history still depends on the original recording pipeline (or its separate MIDI path). Ordinary completed songs are not invented as history entries. Recording, the remaining collection action handlers and manufacturer cloud availability remain incomplete.

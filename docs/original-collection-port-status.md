# Original local song collections

The song-grid favorite buttons now use the APK's active `MuiltCollectListManager` path rather than the older customer-ID DAO. A first favorite opens the translated `CollectLoginDialog` inside the existing control-panel window. Successful login retries that song, saves its ID and refreshes the original collected icon. Clicking again removes it. TV playback continues independently.

`CollectInputPwdView`, `CollectFileManager` and `CollectLoginManager` define the local profiles: four-to-twelve-character names/passwords, slash-to-underscore calibration, automatic profile creation for a new name, password checking for existing names, independent ordered song lists and a remembered current profile. The original `kmbox/muilt_collect/<username>-VietK-<password>` UTF-8 line format is retained below the port's local state directory, with a 150-song addition limit. These are local collection passwords, not manufacturer or YouTube credentials. The original file format exposes the local password in its filename; do not use a password shared with another account. The port never logs these names/passwords or sends them to a server.

The modal follows `dialog_input_pwd.xml` and `view_collect_input_pwd.xml`: 480-wide content, 60-high heading, 288-high form, 245×50 fields, original positions, colors, rounded cyan confirmation button and Vietnamese strings. Windows text/password controls and Escape replace the Android input method/back action. Toast rendering and Android keyboard handling are not identical yet. The original initial `AnimationUtil` direction is zero, which applies no entrance translation. Profile login/logout is also accessible through the panel's existing options menu; the complete original `CollectFragment` sidebar, collection grid, paging and login/logout screen remain to be ported. This does not claim a finished original collection screen.

Windows-incompatible filename characters are rejected. Saves use a temporary file plus replacement, so an unsuccessful save retains the confirmed collection and icons. The collection query retains original ordering: page song IDs before metadata lookup and local/connected-online/PSL filtering. Core checks exercise independent profiles, wrong passwords, restart/logout, insertion order, original file format, an actual locked-file write failure, imported duplicate/invalid IDs, filtering and the limit. Native Windows checks click the real favorite image, confirm the modal, inspect the original confirmed icon and verify persistent removal, cancellation, failed-login field clearing and two-window operation. Reports contain synthetic fixtures only; profile files stay outside report artifacts.

Normal sung history still depends on the original recording pipeline (or its separate MIDI path). Ordinary completed songs are not invented as history entries. Recording, full original collection browsing and manufacturer cloud availability remain incomplete.

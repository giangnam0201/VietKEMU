# Local phone remote

Start the Windows app and connect the phone to the same LAN/Wi-Fi. Scan the TV QR with the phone's camera and open its link in the browser. No phone app, manufacturer account or device serial is needed. This is a local replacement transport, not compatibility with VietK's hosted mobile website.

The remote searches through the PC's existing yt-dlp client and its configured Firefox/cookie session. It adds songs to the real queue, supports sing-now, priority, reorder, remove, shuffle, clear waiting songs, retry, pause/resume, next, replay and volume. Commands use the same Windows playback implementation and TV OSD. Expressions and wishes use the original private supplemental media when available; TV blackout affects the panel preview too. State refreshes once per second; media stays on the PC/TV and is not streamed to the phone.

The app listens on TCP 9167 using Kestrel. Windows Firewall must permit the executable on the private network, and Wi-Fi client isolation must be disabled for LAN connections. The Firefox/options menu opens an in-panel pairing page with a larger QR and a network-address selector, and includes “Ngắt điện thoại cũ / tạo QR mới” to revoke existing sessions. A second app instance can occupy the port; the menu reports startup failure without breaking music playback. The local TV pairing matrix is enlarged to 180 canvas pixels for readability; original manufacturer QR sizing remains separately preserved.

Pairing uses a new random 256-bit secret each app launch. The QR carries it in a URL fragment; the browser removes it from the address and holds it in session storage. API requests require its bearer token. Rotation immediately invalidates old tokens. Tokens, cookies and pairing URLs are not logged or sent to GitHub. Commands reject foreign origins, unrecognized actions and arbitrary media IDs that were not returned by a search. Bodies are limited to 8 KiB and concurrent searches are bounded. This is HTTP for a trusted home LAN, not an internet-facing service; do not forward this port through a router. Multiple active network adapters may require opening the address shown in the menu for the phone's LAN; the QR uses the first active Ethernet/Wi-Fi IPv4 address.

Verification uses real loopback HTTP and native queue callbacks, with a synthetic search provider to avoid YouTube/authentication dependence. It checks unauthorized and cross-origin rejection, search/add, priority/reorder/remove/shuffle/clear, volume with TV feedback, unknown-command rejection, session revocation and the original `order_bg` bottom-button route. Physical phone/Wi-Fi reachability and manufacturer-cloud compatibility are not established by these tests. The phone page is a responsive local interface, not a pixel-for-pixel recreation of the manufacturer's hosted site.
